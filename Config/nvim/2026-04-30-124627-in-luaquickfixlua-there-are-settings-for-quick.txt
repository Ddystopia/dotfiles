● The bug was a classic "identify the chosen buffer by who's active after the
  jump" mistake. :cc from a quickfix window is supposed to switch focus to
  origin_win, but if it doesn't (e.g., in some edge cases or neovim versions),
  vim.api.nvim_get_current_buf() returns the qf buffer itself. That means the
  actual file buffer stays in preview_bufs and gets force-wiped by
  do_wipe_preview_bufs, causing neovim to fall back to origin_buf in origin_win
  — which is the "returned to start" behavior you were seeing.

  The fix adds two things:
  1. pcall around cc — same as do_preview does; if cc fails, we reset committed
  and bail cleanly instead of leaving it stuck as true.
  2. Protect origin_win's buffer in addition to current_buf — so even if cc
  doesn't change the active window, the file that was opened there is excluded
  from the wipe.

❯ How to hot reload? So that old stuff removed and new one applied              

  Read 1 file (ctrl+o to expand)

● True hot reload (old state fully removed, new applied) is not cleanly
  achievable in Neovim without a restart, because require is cached and
  autocmds/keymaps accumulate. The practical options:

  For a single file like quickfix.lua:
  :lua package.loaded['quickfix'] = nil; require('quickfix')
  This clears the module cache and re-runs the file. But autocmds and keymaps
  set by the previous load are not automatically removed — they'll duplicate.
  For quickfix.lua this matters because every reload registers another FileType 
  qf autocmd.

  The clean way — wrap each module in an augroup:

  For quickfix.lua specifically, wrap the FileType autocmd in a named augroup
  with clear = true:
  vim.api.nvim_create_augroup("QuickfixSetup", { clear = true })
  vim.api.nvim_create_autocmd("FileType", {
    group = "QuickfixSetup",
    pattern = "qf",
    ...
  })

  Then on reload, the clear = true wipes the old autocmd before re-registering.
  Same pattern applies to your other modules.

  Restart is the reliable baseline:
  :wqa
  then reopen. With lazy.nvim's cache, startup is fast enough (~50–100ms
  typically) that restart is the pragmatic choice for config changes.

  For keymaps specifically, they're last-write-wins by key — re-sourcing just
  overwrites them, so keymaps don't duplicate.

  The short answer: use augroups with clear = true in each module, then :lua 
  package.loaded['quickfix'] = nil; require('quickfix') for per-file reload. For
   anything complex (lazy.nvim setup, opts, maps), just restart.
